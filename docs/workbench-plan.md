# Web 工作台方案（草案 v0）

> 已被 `docs/tech-solution/` 取代（存储改为 SQLite、扩展离线同步等），本文件仅作历史参考。

## 定位与原则

- 先做 Web 服务版本，桌面端暂缓。本地 Node 服务同时提供采集 API 与工作台页面：`http://127.0.0.1:43118/app`。
- 本地优先：`StudyStudioData` 中的文件是唯一事实源；SQLite 索引、整理结果、知识图谱均为派生数据，可删除重建。
- 原始内容（`inbox`）、整理结果（`system`）、索引（`index.sqlite`）严格分离；整理只读 `inbox`，不改写原文。
- 安全：仅监听 `127.0.0.1`；工作台 API 与采集 API 共用配对令牌鉴权；校验 `Host`/`Origin` 防 DNS rebinding；不开放宽松 CORS；API Key 不回传前端明文。

## 模块与阶段

导航（不分组）：首页、学习区、知识库、学习进度、收集箱；设置分组：AI 配置、采集设置。

不单独做搜索模块：查找学过的内容通过首页对话完成，全文检索作为对话的检索能力保留在后端。

| # | 模块 | 阶段 | 说明 |
| --- | --- | --- | --- |
| 1 | 学习进度 | P1 | 左侧时间线（学习行为与会话），右侧进度纵览（时长、趋势、待处理、来源分布） |
| 2 | 收集箱 | P1 | 网页/问答的列表、详情、状态、标签、排除规则 |
| 3 | 采集设置 | P1 | 扩展连接、学习门槛、站点规则、数据管理 |
| 4 | AI 配置 | P1 | 模型服务商、API Key、按任务选模型、连通性测试 |
| 5 | 学习区 | P2 | 在工作台内阅读 PDF/PPT 等文档，阅读过程被采集（不做网页预览） |
| 6 | 整理 | P3 | LLM 摘要、要点、标签、知识卡片，写入 `system/` |
| 7 | 知识库 | P3 | 左侧目录结构的知识库，右侧知识图谱，两者联动；词条详情页以 wiki 形式阅读 |
| 8 | 首页（对话） | P3 | 用对话询问自己的学习记录与知识库：学过什么、掌握程度、缺什么 |

依赖关系：知识库依赖整理，整理依赖 AI 配置；首页对话依赖知识库与时间线。P3 完成前，首页先展示学习进度摘要与快捷入口，对话框不可用时提示去配置 AI。学习区独立，可与整理并行。

## 模块详情

### 1. 学习进度

时间线与进度纵览合为一页，日期范围（最近 7 / 30 天 / 自定义）对两侧同时生效。

左侧时间线：

- 按天分组展示学习事件：提问、回答完成、网页入箱、备注、有效阅读时长；按事件类型筛选。
- 学习会话：相邻事件（默认间隔 < 20 分钟）折叠为一组，显示会话时长与条目数。
- 条目点击进入收集箱详情。

右侧纵览：

- 正在学习：扩展上报的当前页面与本次可见时长。
- 今日：学习时长（`readingStats` 汇总）、新收网页、问答、备注数；连续学习天数。
- 近 7 天学习时长趋势、来源分布（站点 / 对话平台 / 文档）。
- 待处理：收集箱未读数、待整理数、薄弱知识点，点击跳转。

### 2. 收集箱

- 列表：网页 / 问答 Tab；标题、来源、收集时间、累计阅读时长、收集原因、状态、标签；排序：按收集时间 / 按阅读时长。
- 状态：`unread` → `read` → `organized` → `archived`；支持批量操作。
- 误收处理：删除条目，并可一键生成排除规则（精确 URL / 域名 / URL 前缀）。删除走回收站与知识库级联，见「删除与知识库同步」。
- 网页详情：Markdown 正文渲染、原文链接、阅读记录（每次有效停留与总时长）、关联备注、标签编辑、补写备注。
- 问答详情：问题、回答、DeepSeek 思考过程（可折叠）、所属会话链接。

### 3. 采集设置

- 连接：配对令牌（复制 / 重置）、扩展最后上报时间、离线队列提示。
- 学习门槛：入箱时长、滚动深度、再次停留下限；提供「正式 / 调试」预设，取代 `STUDY_STUDIO_DEV` 环境变量。扩展启动及定时从 `GET /v1/settings` 拉取，无需重新构建。
- 规则：站点黑/白名单、自定义列表页 URL 规则（内置规则只读展示）、对话平台开关。
- 数据：数据目录与占用、导出 zip、重建索引。

### 4. AI 配置

- 布局：页面最上方是「服务商」主从卡片，左侧服务商列表（状态、添加服务商），右侧为选中服务商的配置表单；下方左栏为按任务选模型与自动整理，右栏为今日用量；底部为整理日志。
- 服务商：OpenAI 兼容接口（含 DeepSeek、通义等）、Anthropic、本地 Ollama；可配置多个。
- 字段：Base URL、API Key、默认模型；「测试连接」「保存」按钮，显示该服务商被几项任务使用。
- 按任务指定模型：摘要/整理、知识抽取、向量 Embedding（后续语义搜索用）。
- 用量：按任务记录调用次数与 token，提供每日上限，防止批量整理超支。
- 存储：`state/secrets.json`（文件权限 0600），接口只返回掩码（`sk-…abcd`），不写入日志与导出包。

### 5. 学习区

目标：在工作台内学习的内容天然属于强学习来源（`isStrongLearning: true`），浏览即采集。

- 网页：Web 版不做网页预览。用户已在浏览器中，网页继续在浏览器内阅读并由扩展采集；工作台内的原网页浏览留给后续桌面端内置浏览器。
- PDF：上传或拖入，使用 pdf.js 渲染；记录页码、停留时长、选中/复制文本、备注；原文件存 `inbox/documents/`，同时抽取全文用于搜索与整理。
- PPT/PPTX：首版抽取每页文本按页渲染；可选依赖 LibreOffice 转 PDF 后复用 PDF 阅读器。
- 采集：沿用学习门槛与阅读时长规则；事件 `source.channel` 新增 `workbench`；新增 `document_captured` 事件类型。

### 6. 整理

整理即把收集箱条目通过 LLM 写入个人知识库：摘要、要点、标签、知识卡片（问答形式），并抽取概念与关系进入知识图谱。

- 产物：`system/items/<itemId>.json`（摘要、要点、卡片），记录所用模型与提示词版本，可重跑覆盖；概念与关系写入图谱。
- 收集箱条目状态在整理完成后变为 `organized`；被删除或原文变化的条目会重新进入待整理。

#### 触发方式（可同时开启，在 AI 配置中设置）

| 触发 | 默认 | 说明 |
| --- | --- | --- |
| 手动 | 始终可用 | 单条 / 批量 / 「立即整理」全部待整理条目 |
| 每天定时 | 开，23:00 | 整理当天新增的未整理条目 |
| 攒够数量 | 开，10 条 | 未整理条目达到 N 条即跑一批 |
| 入箱即整理 | 关 | 每收一条立即生成摘要，token 消耗最大 |

- 调度：服务内单一任务队列串行执行，同一时间只跑一批；多个触发同时命中合并为一次。
- 补跑：服务未运行错过定时，下次启动时补跑一次（不补多次）。
- 限额：受 AI 配置的每日 token 上限约束；达到上限时暂停，剩余条目留到次日，不丢弃。
- 增量：只处理 `pending` 条目（新增、原文变化、上次失败），已整理且未变化的条目不重复消耗。
- 失败：单条失败（如超出上下文长度、接口报错）记录原因并跳过，不阻塞整批；日志中可「重试失败项」。

#### 整理日志

每次运行写入 `system/runs/<runId>.json`，AI 配置页展示列表：时间、触发方式、处理条目（成功 / 失败及原因）、知识库变化（新增 / 更新知识点与关系数）、token 用量、模型。

### 删除与知识库同步

用户删除收集箱条目时，可选择同时从知识库移除由它整理出的内容。前提是所有整理产物都记录来源：

- 知识点 / 关系：`sources: [itemId]`，以及 `evidence: [{ itemId, quote }]`（支撑该知识点的原文片段）。
- 摘要 / 卡片：一条产物对应一个 `itemId`。

删除弹窗先展示「知识库影响预览」，确认后执行：

| 产物 | 处理 |
| --- | --- |
| 该条目的摘要、卡片 | 删除 |
| 只来自该条目的知识点 | 删除，相关边一并删除 |
| 还有其他来源的知识点 | 保留，从 `sources`/`evidence` 移除该条目，标记 `stale`，下次整理用剩余来源重写描述 |
| 用户手动编辑过的知识点（`userEdited`） | 不自动删除，仅移除来源；若已无来源则标记「无来源」，由用户决定 |
| 两端仍存在、但来源只有该条目的边 | 删除 |

- 回收站：删除先进入回收站，保留 30 天；期间「撤销删除」恢复条目及被移除的知识点与边（快照记录在回收站条目中），「彻底删除」立即清理原文件。
- 可选同时生成排除规则（精确 URL / 域名 / URL 前缀），避免再次收集。
- 用户也可在知识库中直接删除知识点，不影响原始条目。

### 7. 知识库

目录与图谱是同一份数据（`nodes.jsonl` / `edges.jsonl`）的两种视图，合在一个页面：左侧目录便于按结构浏览，右侧图谱便于看关系。

- 左侧目录：一级为分类，分类下按 `part_of` 关系逐级嵌套（如 RAG → 重排 → 交叉编码器）；每项显示掌握度色点、百分比、`stale` / `userEdited` 标记；分类可折叠，显示词条数与平均掌握度。顶部支持按名称/别名搜索、按类型筛选（搜索或筛选时改为平铺结果）。
- 联动：选中目录中的词条，图谱点亮该节点及其直接关联节点与边，其余变暗；选中分类则点亮该分类全部节点；点击图谱节点同样会选中目录项。图谱下方信息条显示选中项的简介、掌握度、来源数，以及「查看详情」。
- 详情：目录项悬停或选中时出现「详情」按钮，进入词条详情页。
- 分类：整理时由 LLM 归类（如「RAG 系统」「检索基础」「模型与架构」），用户可改名、合并、移动词条；未整理的内容显示在「未归类」。
- 类型：概念、方法、算法、模型、论文，用于筛选。
- 词条详情页（wiki）：概述、要点、关联词条（属于 / 组成部分 / 前置知识 / 对比 / 相关，互相跳转）、知识卡片、我的笔记、来源摘录（`evidence`）；侧栏为掌握程度、来源列表、同分类词条；可「在图谱中查看」回到知识库并选中该节点。
- 编辑：用户可修改词条或新建词条，标记为 `userEdited`，后续整理不覆盖手动内容，只追加来源与建议。

图谱数据：

- 节点：概念 / 知识点（名称、别名、简介、掌握程度、`sources`、`evidence`、`userEdited`、`stale`）；每个节点回链来源条目（网页、问答、文档段落）。
- 边：`prerequisite`（前置）、`part_of`（组成）、`related`（相关）、`contrasts`（对比）。
- 构建：整理阶段由 LLM 抽取候选概念与关系，按名称/别名合并去重；用户可手动合并、改名、删边。
- 存储：`system/graph/nodes.jsonl`、`edges.jsonl`，导入 SQLite 供查询。
- 展示：力导向图，按关系类型筛选；后续结合知识卡片做间隔复习。

### 8. 首页（对话）

用户进入工作台的第一屏是对话框，问的是「自己学过的东西」，回答必须基于学习记录与知识库并标注依据。

- 空状态：问候与今日学习时长、输入框、示例问题、三个入口卡片（今日学习、知识库、薄弱知识点）。
- 典型问题与数据来源：

| 问题类型 | 示例 | 检索来源 | 回答内容 |
| --- | --- | --- | --- |
| 时间范围回顾 | 我今天学了什么 / 最近一周学了哪些 | 时间线、学习会话 | 时长、会话主题、涉及知识点、建议继续的内容 |
| 知识点询问 | RAG 到底是什么 | 知识库词条、关系、来源摘录 | 定义与要点、组成部分及各自掌握程度、未覆盖的部分、建议先补的知识点 |
| 掌握情况 | 我哪些知识掌握得不好 | 掌握程度、阅读时长、复习结果 | 薄弱 / 熟悉列表与学习路径建议 |
| 未学过 | 什么是 k8s | 无命中 | 说明知识库没有相关内容；可选用模型通用知识回答，明确标注「非学习记录」 |

- 实现：意图识别 → 检索（时间线按时间范围查询；知识点走 FTS + 向量检索词条与来源）→ 组装上下文 → LLM 生成；回答底部列出依据（词条、学习记录），可点击跳转。
- 对话本身不计入收集箱和学习时长；对话记录保存在 `state/chats/`，可清空。
- API：`POST /v1/chat`（流式返回，附带引用列表）。

## 技术方案

- 前端：React + Vite + TypeScript，`react-router`、TanStack Query；图谱可视化候选 Cytoscape.js / React Flow。
- 后端：在现有 `local-ingestion` 服务上扩展，静态托管前端构建产物于 `/app`。
- 索引：SQLite（`StudyStudioData/index.sqlite`），启动时增量同步 `timeline` / `inbox` / `system`；FTS5 全文表供首页对话检索。FTS5 默认分词不支持中文，入库前用 `Intl.Segmenter('zh', { granularity: 'word' })` 分词（或用 `trigram` tokenizer 兜底）。
- 状态文件（`StudyStudioData/state/`）：`items.json`（状态、标签）、`rules.json`（排除规则）、`settings.json`（门槛等）、`secrets.json`（API Key）、`organize.json`（自动整理设置、上次 / 下次运行时间、待整理队列）、`trash.json`（回收站条目、删除时间、被移除知识点与边的快照）。
- 整理产物（`StudyStudioData/system/`）：`items/<itemId>.json`、`graph/nodes.jsonl`、`graph/edges.jsonl`、`runs/<runId>.json`。回收站中的原文件移入 `trash/`，到期清理。

建议目录：

```text
apps/workbench/                 React 前端
services/local-ingestion/src/
  ingestion-server.js           采集 API（现有）
  workbench/                    工作台 API、索引同步、设置与规则
  ai/                           模型服务商适配、整理任务队列（P3）
packages/collector-runtime/     采集运行时（现有）
```

## API 草案

| 方法与路径 | 用途 |
| --- | --- |
| `GET /v1/workbench/overview?range=7d` | 学习进度纵览统计 |
| `GET /v1/workbench/timeline?from&to&types&source` | 时间线（含会话聚合） |
| `GET /v1/workbench/items?type&status&tag&cursor` | 收集箱列表 |
| `GET /v1/workbench/items/:id` | 条目详情（正文、阅读记录、备注） |
| `PATCH /v1/workbench/items/:id` | 修改状态、标签、备注 |
| `GET /v1/workbench/items/:id/impact` | 删除前的知识库影响预览 |
| `DELETE /v1/workbench/items/:id` | 移入回收站；参数：是否同步移除知识库、是否生成排除规则 |
| `GET /v1/workbench/trash`、`POST /v1/workbench/trash/:id/restore`、`DELETE /v1/workbench/trash/:id` | 回收站：列表、撤销删除、彻底删除 |
| `GET/PUT /v1/settings` | 学习门槛与采集设置（扩展也读取） |
| `GET/POST/DELETE /v1/rules` | 排除规则 |
| `GET/PUT /v1/ai/providers`、`POST /v1/ai/providers/:id/test` | AI 配置 |
| `POST /v1/workbench/documents` | 学习区：上传 PDF/PPT（P2） |
| `GET/PUT /v1/organize/settings`、`POST /v1/organize/run`、`GET /v1/organize/runs` | 自动整理设置、立即整理、整理日志（P3） |
| `GET /v1/graph`、`PATCH/DELETE /v1/graph/nodes/:id` | 知识图谱查询与编辑（P3） |
| `GET /v1/wiki`、`GET /v1/wiki/:id`、`POST /v1/wiki` | 知识库分类与词条、新建词条（P3） |
| `POST /v1/chat` | 首页对话，流式返回并附带引用（P3） |

## 推进顺序

1. P1 后端：SQLite 索引同步、工作台 API、设置/规则/AI 配置存储、`Host`/`Origin` 校验。
2. P1 前端：收集箱（列表 + 详情）→ 学习进度（时间线 + 纵览）→ 采集设置 → AI 配置。
3. 扩展改为从 `/v1/settings` 动态拉取门槛与排除规则。
4. 打包 `npx study-studio` 一条命令启动，开源发布。
5. P2 学习区：PDF → PPT。
6. P3 整理 → 知识库（目录 + 图谱 + 词条页）→ 首页对话 → 复习。

开发前先用 `prototype/workbench/` 的 HTML 原型（假数据、可点击）验证模块与交互是否合理，再据此修订本方案。
