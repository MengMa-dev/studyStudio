# 08 知识库（目录 + 词条详情）

> 本期不做知识图谱可视化（S14）。下文标「后续」的内容不在本期实现；`kb_edges` 照常写入，供目录嵌套与关联词条使用。

## 页面

- 页面高度 = 可视区高度，不出现整页滚动；左侧目录与右侧面板各自滚动。
- 右侧面板（替代原型中的图谱区）：显示当前悬停/选中词条的预览——简介、掌握度、来源数、关联词条、「查看详情」；多选时显示已选列表与批量操作；未选中时显示分类概况（词条数、平均掌握度、薄弱词条）。
- 顶部编辑区：搜索（名称/别名）、类型下拉筛选（概念/方法/算法/模型/论文）、「整理」「删除」按钮（作用于多选项，显示已选数量）。
- 左侧目录：
  - 一级为分类，分类下按 `part_of` 逐级嵌套（如 RAG 系统 → 重排 → 交叉编码器）。
  - 每项：掌握度色点 + 百分比、`stale`/`user_edited`/无来源标记；标题单行省略 + tooltip。
  - 交互：整行可点击；分类行点击展开/折叠；普通词条点击进入详情；仅点击 checkbox 选中；hover 显示删除按钮。
  - 多选：选中项汇总到右侧面板。搜索/筛选时改为平铺结果。
- 后续（图谱）：右侧改为图谱，选中词条点亮该节点及直接关联节点与边，其余变暗；点击节点同步选中目录项。
- 不提供合并节点、新建词条。

## 词条详情（wiki）

- 面包屑：最左侧「返回」按钮；每级可点击（分类 › 父词条 › 当前）。
- 正文：AI 整理后的完整内容（Markdown，不叫「要点」），由整理时的新词条正文 + 后续补丁组成（见 07 ⑤⑥）；知识卡片本期不做。有素材时正文后由程序渲染「与 X 的区别」（来自 `contrasts` 边与其 `description`）与「常见疑问」（来自问答来源中的用户问题）段落，不存入正文。
- `patch_count ≥ 8` 时显示「建议重新整理」提示（见 07 ⑦）。
- 侧栏：掌握程度（可手动设定）、我的笔记（知识点备注，随时新增/编辑）、来源列表、同分类词条、关联词条（属于/组成/前置/对比/相关）、来源摘录（evidence）。
- 问答来源：知识库不单独存储问答，问答作为来源条目；来源摘录展示「问题 + 回答摘录」，点击回到收集箱中对应那一轮问答。
- 「在知识库中定位」回到知识库并在目录中展开、选中该词条（图谱上线后改为「在图谱中查看」）。
- 编辑：头部「编辑」→ 同位置「保存/取消」；保存置 `user_edited=1`、`dirty`，不自动整理，显示待整理提示条。
- 删除：目录 hover 与详情页均可删除；弹窗说明删除正文、笔记与 n 条关系，子词条上移到最近存活的父级，来源条目保留在收集箱；可勾选「以后整理时不再自动生成」→ 写 `kb_ignore`。删除进入回收站可撤销。

## 掌握度

- 自动估算（`mastery_source=auto`），整理后与阅读后重算：

```text
mastery = clamp( 0.35·来源数得分 + 0.35·阅读时长得分 + 0.2·问答次数得分 + 0.1·备注得分 , 0, 1 )
各项得分 = 1 - exp(-x / k)，k 为经验常数；无来源时保持原值
```

- 用户手动设定后 `mastery_source=user`，不再自动覆盖，可「恢复自动」。
- 后续复习功能上线后，以复习结果为主要因子。

## API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /v1/kb/tree?q&kind` | 分类 + 嵌套目录（递归 CTE 计算） |
| `GET /v1/kb/graph` | 节点与边（后续，图谱上线时提供） |
| `GET /v1/kb/entries/:id` | 详情：正文、备注、来源与 evidence、关联、完整度 |
| `PATCH /v1/kb/entries/:id` | 编辑正文、掌握度、分类 |
| `GET /v1/kb/entries/impact?ids` / `DELETE /v1/kb/entries` | 删除预览 / 删除（ids、ignore） |

## 选型

### S14 图谱可视化（结论：本期不做；以下对比留作后续参考）

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| ★ Cytoscape.js（+ cytoscape-fcose 布局） | 图模型 API 完善（邻居查询、类选择器高亮/变暗一行完成）；样式表声明式；千级节点流畅；与框架无关 | 默认视觉偏朴素，需写样式贴合原型 |
| AntV G6 v5 | 中文文档、内置交互与动画丰富、视觉好 | 体积大，v4→v5 API 变化大 |
| Sigma.js + graphology | WebGL，万级节点 | 交互与样式定制成本高，本项目规模用不到 |
| react-force-graph | 上手快（d3-force） | 高亮/标签/布局控制弱 |
| React Flow | 节点可放 React 组件 | 面向编辑器，无力导向布局 |

### S15 目录树组件

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| ★ 自研（递归组件 + 展开/选中 store） | 交互细节（整行点击 / 仅 checkbox 选中 / hover 删除 / 掌握度）完全贴合原型；词条数百级无需虚拟化 | 键盘导航与无障碍需自己补 |
| Headless Tree（react-complex-tree 继任） | 无样式、可访问性完善、支持多选与虚拟化 | 需要适配点击语义 |
| react-arborist | 虚拟化、拖拽 | 自带交互模型较强，定制「仅 checkbox 选中」需绕 |
| Ant Design Tree | `checkable` 开箱即用 | 引入 AntD 视觉体系，与原型风格冲突 |

### S16 内容编辑器（收集箱正文、词条正文共用）

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| ★ CodeMirror 6（Markdown 模式）+ 预览 | Markdown 原样保存无损；代码块、公式不变形；体积适中 | 非所见即所得 |
| 纯 textarea（原型做法） | 零依赖 | 无高亮、长文编辑体验差 |
| Milkdown（ProseMirror，Markdown 优先） | 所见即所得且以 Markdown 为存储 | 表格/公式插件需配置，往返可能有格式差异 |
| TipTap / BlockNote | 编辑体验最好 | 以 JSON 为主存储，Markdown 往返有损 |

正文渲染：`react-markdown` + `remark-gfm` + `remark-math`/`rehype-katex` + `shiki`（代码高亮）。
