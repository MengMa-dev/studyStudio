# 09 首页对话与悬浮对话

## 功能

- 首页：问候 + 今日学习时长、输入框、示例问题、入口卡片（今日学习、知识库、薄弱知识点）；未配置 AI 时提示去配置。
- 悬浮对话：知识库、学习进度、收集箱及各详情页右下角圆形 icon 按钮；点击页面其他区域收起。
- **首页与悬浮对话共用同一会话**，消息实时同步（同一 `session_id`，前端同一 query cache）。
- 页面上下文：悬浮对话发送时附带 `context`（路由、itemId / entryId / 已选词条 / 当前页码），示例问题随页面变化（如「这篇文章讲了什么」「这个知识点讲解是否完整」）。
- 回答必须基于学习记录与知识库，底部列出依据（词条、学习记录）可点击跳转；无命中时说明「知识库没有相关内容」，可选用通用知识回答并标注「非学习记录」。
- 对话不计入收集箱与学习时长；可清空。

## 整理意图

| 输入 | 所在页面 | 行为 |
| --- | --- | --- |
| 「帮我整理该页知识点」 | 条目详情 / 词条详情 / 阅读器 | 自动识别当前目标，返回「整理确认卡片」（预填要求），确认后走 07 的手动整理 |
| 「整理」（无明确范围） | 词条详情 | 反问：整理当前知识点 / 所有未整理内容 / 全量 |
| 「整理」 | 其他页面 | 反问：待整理 / 全量 / 已选（有已选时） |

任何整理都需用户在卡片中确认，模型不能直接执行写操作。

## 实现

```text
POST /v1/chat  { sessionId, message, context }   → SSE 流（AI SDK UI message stream）
  1. 组装系统提示：用户身份、当前日期、页面上下文摘要、回答规则（必须引用依据）
  2. streamText + tools（模型自行决定调用）：
       query_timeline(from, to)            时间线与学习时长
       search_knowledge(query, k)          混合检索：FTS5(bm25) + 向量，RRF 融合，返回词条/条目片段
       get_entry(id) / get_item(id)        当前上下文对象全文
       list_mastery(level)                 薄弱/熟悉列表
       propose_organize(scope, targetIds, requirement)  只返回确认卡片数据，不执行
  3. 流结束：写 chat_messages（含 citations、tool 结果摘要）
```

- 不支持 tools 的模型：降级为「规则意图识别（时间词 / 整理关键词）→ 固定检索 → 单轮生成」。
- 引用：tool 返回的每条结果带 `ref`，模型按 `[1]` 标注，服务端校验 ref 存在后生成依据列表。

## 选型

### S17 对话 UI 与流式协议

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| ★ AI SDK UI `useChat` + 自研界面 | 与后端 `streamText` 协议原生配套（流式、tools 结果、自定义数据块如确认卡片）；UI 完全按原型绘制；同一 `id` 天然支持首页与悬浮同步 | 消息持久化与加载需自己接 |
| assistant-ui | 现成聊天组件（流式、Markdown、工具 UI），可接 AI SDK | 视觉与原型差异需覆盖样式；多一层抽象 |
| 全自研 SSE 协议与 UI | 无依赖 | tools 调用、流式中断、重连都需自写 |

检索相关能力（FTS5、sqlite-vec、Embedding 模型）见 02、06。
